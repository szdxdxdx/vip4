
各模块的逻辑划分如下：
- pi_agent：主要负责与 Pi Agent 进行 RPC 通信，对 pi 的包装层
  负责与 Pi Agent 进行 RPC 通信，提供对 pi 的包装层。完全独立于 vip_task 模块，vip_task 模块只依赖 pi_agent 模块。不包含任何业务逻辑代码。
  目前只需要实现与业务逻辑相关的 RPC 接口即可。提供：pi 进程的启动、停止、状态查询、消息发送、消息接收等接口。
- vip_task：主要负责【软件 IP 验证】任务的管理
  - task_manager：主要负责多个验证任务的管理，创建、查询
  - task： 负责管理单个验证任务，包含：项目目录结构的管理、相关文件管理、pi 进程创建和维护、与 pi 的通信等
- service：主要负责对外提供服务接口
  - api：主要负责对外提供 HTTP 接口

实际代码目录结构如下：
```
server/
|   app/
|   |   agent/
|   |   |   pi.py
|   |   vip_task/
|   |   |   task_manager/
|   |   |   task/
|   |   service/
|   |   |   api.py
|   app.py
|   config.py
```

python 包名或模块名需要与业务模块名一致
开发前期可以使用单个 .py 文件实现业务模块，后期代码复杂后则改称目录
python 包实现的业务模块，除了包含业务模块核心逻辑代码外，还可以包含
config.py、types.py、utils.py 等

开发过程中可以适当重构已有的业务模块

下层模块不要依赖于上层模块，保持模块独立
