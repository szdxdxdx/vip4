## 项目验证使用

顶栏选择“项目验证”，选择输入来源并输入项目 ID，提示词可留空使用后端默认 CBMC。来源默认课题二，创建请求省略默认 source；课题三显式发送 `source: keti3`。两来源共用项目 ID 命名空间，不允许同 ID 分别创建两个项目。点击“提交验证”创建项目；已有项目选择“查询已有项目”。页面每 2 秒串行查询进度与结果，完成、失败、取消或无任务时停止。请求错误后可手动查询重试；普通提交不会覆盖项目。“强制提交验证”需确认，会先停止同 ID 旧验证并永久删除该项目旧任务文件及数据库映射，切换来源也不例外；不存在的项目也可使用。重置中继续轮询，成功后刷新工作台历史和选择，保留创建表单输入。

切换回单 IP 工作台不会清空输入或中断任务订阅，项目自动查询会暂停，返回后续查。修改项目 ID 或输入来源会清除旧项目展示并停止查询，迟到进度与结果不能污染新展示。查询按 ID 查找，不以所选来源推断已有项目来源；进度响应可选的 `source` 用于显示实际来源，缺字段时不显示来源。每个任务可下载结果文件，也可用“查看任务”返回单 IP 工作台查看会话。

“删除项目”需永久删除确认，调用 `POST /project/delete_project`，请求体为 `{projectID}`，成功返回 `{projectID, status: 'deleted'}`。404 表示不存在，409 表示并发清理；失败不假删，可手动查询重试。删除或强制提交成功清除旧项目快照，复用工作台历史刷新通知，作废旧列表、详情和订阅；其他仍存在任务的选择和聊天草稿及创建表单保留。若历史刷新失败，不展示旧任务，使用工作台“刷新”重试。

课题二收集多个 IP 分别验证。课题三按项目 ID 通过上游 `POST /api/verify` 下载已有合成产物的全部 ZIP，不调用 synthesize，构建单个任务，IP 标识为 `keti3:<projectID>`。后端保存原始 ZIP 为任务根目录 `keti3.zip`，全部文件解压到 `input/` 并保留目录。`IR/` 为形式模型，根目录 C/H 是主 IP，`iplib/` 是依赖；没有 IR 时 Agent 须明确报告缺模型，不能当作有模型验证。前端只调用项目接口，不直接下载上游产物。

项目任务卡以 IP 标识为主标题，来源为进度接口的 `tasks[].ip_id`，对应上游 `ipMsg.entity.basicInformation.id`（如 `B_TcProcess`），不是数字 `ipId`，也不是 IP 名称 `name`。卡片另行显示明确标注的“任务ID”；历史任务的空值或缺字段显示“未提供 IP 标识”，仍可用任务 ID 区分。进度和结果接口的任务类型均包含 `ip_id`，结果文件匹配与“查看任务”仍使用 `task_id`。此展示仅用于项目页，单 IP 工作台保持原有功能。

单 IP 聊天使用与历史归约见 [聊天交互](聊天交互设计.md)。
