# 前端工作台

- `src/App.vue`：项目验证与任务详情切换，连接任务订阅和视图。
- `src/components/ProjectPanel.vue`：统一提交表单、查询、紧凑任务表和集中消息区。
- `src/composables/useProject.ts`：提交、任务列表手动查询和迟到响应隔离。
- `src/components/TaskSidebar.vue`：详情页的任务选择、任务 ID/状态及删除错误提示，不触发删除。
- `src/components/ConversationPanel.vue`、`MessageItem.vue`：对话、思考、工具输出和发送/暂停。
- `src/components/ProgressPanel.vue`：实际工具执行进度。
- `src/components/ArtifactPanel.vue`：隔离报告预览、展开阅读、单文件与整任务 ZIP 下载。
- `src/composables/useWorkbench.ts`、`eventReducer.ts`：任务详情、会话草稿、事件归约与竞态隔离。
- `src/api.ts`、`projectApi.ts`：任务与项目 HTTP 接口。
- `src/types.ts`、`projectTypes.ts`：任务显示和来源类型。
- `src/templates/attical.ts`：可手动填入的 AttiCal 单 case 演示提示词。
- `tests/workbench.test.mjs`：真实模块、组件与请求契约测试。

## 使用方法

默认进入“项目验证”。左栏选择 `local`、`keti2` 或 `keti3`：本地任务选择数据集 IP，无需项目 ID；课题任务输入项目 ID。所有来源均可选择 CBMC、CPAchecker、KLEE，默认 CBMC，提交时传递所选工具至后端执行。任务 ID 均由后台生成。

提示词可留空，有内容时作为最高优先级用户要求。只有点击提示词旁的模板小字才填入 AttiCal / CBMC 单 case 测试内容；选择类别或 IP 不改动提示词。模板输入路径为任务 `input/`，后台替换任务 ID。

课题二和课题三以“来源 + projectID”区分。同一项目可重复提交，无需确认，不覆盖或删除已有任务。后台为每次提交生成 UTC timestamp，同批多个 IP 共用，不同批次分别保留。删除仅按 taskID 在任务详情中操作。

右栏任务表点击“查询”或“全部”时请求；挂载和返回页面不自动刷新，本地提交保持手动查询，keti2/keti3 成功提交后延迟 1 秒刷新一次，不轮询。切查询、隐藏或卸载取消延迟刷新并隔离迟到请求。可按 projectID、taskID 精确查询，二者同时填写时取交集。按 projectID 查询显示全部批次，不按 timestamp 分组或过滤。表格依次显示 taskID、projectID、IP 名字、验证情况、时间、操作，表头固定在表格滚动容器顶部。时间列原样显示后台 UTC 时间，新记录格式为 `YYYY-MM-DD HH:mm:ss.ffffff`，历史迁移值为 `2026-10-14 00:00:00`，未知值显示“—”。提交成功刷新任务详情列表并保留已有选择与草稿。消息区按发生顺序向下追加，消息间用横线分隔；提交忙态、成功与失败、列表请求错误及批次状态快照保留，不随查询清空或页面切换删除。内部批次仍可更新用于查询，日志不改写历史；同批次状态、原因和 taskID 不变时不重复追加，不同批次及每次请求失败分别记录。消息区独立手动滚动，浏览历史时不会自动拉回底部。本次会话的远程提交批次消息中，提示前缀仅显示已创建的 taskID，多任务用顿号连接；暂无 taskID 只显示状态及原因，不显示来源、projectID 或时间戳。每次列表刷新同时查询 get_progress，内部按来源、projectID 和精确 timestamp 匹配，不生成占位 taskID；查询或打包失败、空项目及下载失败原因均可手动刷新查看。空项目 ID 显示“—”，历史来源 NULL 不推断为课题二。缺失实际任务目录或元数据会提示，不自动删除记录。

点击“查看详情”进入任务详情页，可选择对话、进度、报告与下载。文件下载支持整个任务 ZIP，包含输入、会话和验证产物。详情左栏 IP 名字独占主行，任务 ID 与状态同行小字。右栏四个视图按钮下用分割线独立放置“删除当前任务”，支持删除目录已缺失的记录；删除前确认，无选择或删除中禁用，忙态可读，错误仍在左栏显示。

左右栏填满可用视口，内容溢出分别滚动；窄屏上下排列。切换页面保留提交输入、查询和对话草稿，隐藏项目页取消未完成的列表请求，返回后需手动查询。报告使用隔离 iframe，展开阅读采用原生 dialog。聊天使用与历史归约见 [聊天交互](聊天交互设计.md)。
